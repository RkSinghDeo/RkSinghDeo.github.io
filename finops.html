The Situation

A Fortune 500 wealth-management firm (one of several clients ranging from early-stage startups to enterprise) with 200+ Lambda functions all provisioned for peak load and never revisited. 40+ Glue jobs running on fixed DPU allocations that hadn't been tuned since launch. Monthly AWS bill hovering around $96,000.

Finance was asking hard questions. Engineering said "we don't know what's driving it." No one had a dashboard. No one had ever run a right-sizing analysis. Cost Explorer showed the categories but not where to cut.

They needed someone to audit first, then build a system that would catch it automatically going forward.

What I Built

Architecture
graph LR EB["EventBridge nightly 02:00 UTC"] --> CE["Cost Explorer Export Lambda"] EB --> GA["Glue Audit Lambda"] EB --> RS["Right-Sizing Lambda"] CE -->|JSON Lines| S3[("S3 Report Bucket")] GA -->|Reports| S3 RS -->|Recommendations| S3 S3 --> ATH["Athena finops workgroup"] ATH --> DASH["Streamlit Dashboard"] RS --> SFN["Step Functions Lambda Power Tuner"] SFN -->|"128→3008 MB"| TARGET["Target Lambda functions"] SFN -->|cost+speed| RS
  • Right-sizing audit Lambda: Pulls 14-day CloudWatch P99 memory metrics for every function. Flags anything using less than 40% of its provisioned memory. Estimates savings, writes nightly S3 report.
  • Lambda Power Tuning via Step Functions: Runs 7 memory configs (128MB to 3008MB) against each flagged function. Finds the optimal cost-per-invocation point, not just the fastest.
  • Glue DPU audit: Reads GetJobRuns history for 30 days. Flags jobs where auto-scaling would reduce DPU cost. Generates Glue config patches ready to apply.
  • Athena + Streamlit dashboard: Self-service cost queries updated nightly. Engineers can explore by service, function name, or job tag without touching Cost Explorer.
  • Bedrock FinOps Analyst: Claude 3.5 Sonnet reads nightly reports via Amazon Bedrock. Emails a plain-English exec summary with top 5 actions by savings potential. Runs at 03:00 UTC.
