01 / The Brief

The Brief

A product data team was handling 20+ ad-hoc analyst SQL requests per week. Business stakeholders wanted revenue cuts, cohort breakdowns, and funnel metrics but lacked SQL skills. The analyst backlog was growing and confidence in the numbers was dropping because requests were slow and inconsistently formatted.

The brief was clear: give business users a plain-English interface over the existing Iceberg Gold layer on Athena. No new BI tools, no new data stores. Read-only, with PII access blocked at the architecture level, not just the policy level.

02 / What Was Delivered

What Was Delivered

Architecture
graph LR USER["Business User Slack / Web / API"] -->|"natural language"| AGENT["Amazon Bedrock Agent Claude 3.5 Sonnet"] AGENT --> PREP["Lambda Validator blocks writes"] AGENT --> EXEC["Lambda Athena Executor"] EXEC --> ATH["Amazon Athena"] ATH --> ICE[("Iceberg Gold Layer S3 + Glue Catalog")] ATH --> S3R[("S3 Query Results")] EXEC -->|"structured data"| AGENT AGENT -->|"plain-English answer"| USER
  • Amazon Bedrock Agent with a custom action group wired to Athena run query, list tables, describe schema
  • Input validation Lambda rejects queries containing write keywords (INSERT, UPDATE, DELETE, DROP, CREATE, ALTER) before they reach Athena
  • Agent grounded on the Iceberg Gold layer only staging and raw tables are outside its scope by IAM policy
  • Structured prompt instructs the agent to explain what it queried, surface row counts, and flag when results might be stale
  • CDK-deployed with scoped IAM roles: agent execution role has athena:StartQueryExecution and s3:GetObject on results bucket only
